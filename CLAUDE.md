# instudy_transkrib — правила для агентов

Сервер автоматической транскрибации для сервиса «Моё расписание» ([Mihanikuz/instudy](https://github.com/Mihanikuz/instudy)). Безголовый демон на домашнем GPU-сервере: сам забирает из instudy работу (pull), скачивает аудио лекции, делает диаризацию (pyannote community-1) и распознавание (GigaAM v3_e2e_rnnt), отправляет обратно два файла — `.vtt` и `.txt`. Работа идёт по плану `docs/plan.md`; каждая задача — один PR.

## Источники истины

| Что | Где | Кто меняет |
| --- | --- | --- |
| Контракт с instudy | `docs/contract.md` (черновик) → после слияния BE-15…BE-17 в instudy — раздел «Сервисный API» в `instudy/docs/api.md` | Только задачи, где это сказано явно (T-4, T-9) |
| Архитектура | `docs/architecture.md` | Только задачи, где это сказано явно |
| Принятые решения | `docs/decisions/*.md` | Только человек |
| План, волны, статусы | `docs/plan.md` | Оркестратор |

Если код и документ расходятся, а задача не разрешает менять документ — не «чини» молча, а опиши расхождение в PR. Если `docs/contract.md` расходится с `instudy/docs/api.md` — прав instudy; опиши расхождение в PR.

## Зафиксировано (не пересматривать без человека)

- Модели: ASR — GigaAM `v3_e2e_rnnt` (пунктуация и нормализация), диаризация — `pyannote/speaker-diarization-community-1`. Других моделей, CPU-режима, LLM, NER и подстановки имён нет.
- Только NVIDIA CUDA. Видеокарта (RTX 5060 Ti 16 ГБ, sm_120) целиком наша; одна работа за раз.
- Полностью офлайн после разовой загрузки моделей: `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, `PYANNOTE_METRICS_ENABLED=0`. Демон ходит в сеть только к `INSTUDY_API_URL`.
- Только pull: входящих портов нет, instudy к нам не подключается.
- Результат — `.vtt` (голоса `<v Спикер N>`) и `.txt` (`[ЧЧ:ММ:СС] Спикер N: текст`). Спикеры нумеруются по порядку первого появления. Форматы — `docs/contract.md`, «Формат результата».

## Стек и раскладка

- Python 3.12 (если колёса torch/pyannote/GigaAM не встают — 3.11, как в gigascribe; решение фиксируется в T-1). torch/torchaudio под CUDA 12.8, pyannote.audio 4.x, GigaAM из git с закреплённым коммитом, httpx, pydantic-settings.
- Пакет `transkrib/`, точки входа: `python -m transkrib` (демон) и `python -m transkrib.cli` (CLI).
- Модули: `config` · `log` · `types` · `client` (instudy) · `audio` (ffmpeg) · `diarize` · `asr` · `segment` · `pipeline` · `render` · `daemon` · `state` · `models_store` · `cli`.
- `asr`, `diarize` и всё, что импортирует torch, gigaam или pyannote, — за интерфейсами (`Protocol`), чтобы остальной код и тесты работали без GPU и без этих пакетов. Тяжёлые импорты — только внутри методов `load()`.

## Безопасность — обязательна в каждой задаче

- `SERVICE_TOKEN` и подписанные ссылки на аудио (`audioUrl` целиком, включая query) никогда не попадают в логи, исключения, `state.json` и тексты ошибок, отправляемые в instudy. Логгер маскирует их фильтром; тест на утечки — обязательный.
- Текст транскриптов в логи не пишется (только длины и счётчики).
- Контейнер не от root, файловая система только для чтения, кроме `data/`; `models/` монтируется только для чтения.
- Ответы instudy — недоверенные данные: проверяй типы и размеры (`audioSizeBytes` не больше лимита, `dayId` — положительное целое, пути строятся только из `job.id`, а не из присланных строк).
- Причина отказа (`fail.reason`) — машинный код из списка в `docs/contract.md` + короткий текст без путей, токенов и трассировок.

## Как работать над задачей

1. Ветка `task/<ID>-<кратко>` от свежего `main`.
2. Прочитай промт задачи в `docs/tasks/<ID>.md` и разделы документов, на которые он ссылается.
3. Пиши тесты вместе с кодом; критерии приёмки из промта — это тесты, а не пожелания.
4. Перед PR: `ruff check .`, `ruff format --check .`, `pytest`.
5. Не трогай файлы чужих задач. Нужна правка общего файла сверх одной строки — опиши в PR, зачем.
6. Описание PR: что сделано, как проверено, какие критерии приёмки закрыты, что проверяет только человек на GPU-сервере, что осталось или вызвало сомнения.

## Тесты

- Тесты не требуют GPU, моделей, сети и настоящего instudy. ASR и диаризация — фейковые реализации интерфейсов; instudy — фейковый сервер (`tests/fake_instudy.py`, httpx `MockTransport` или ASGI-приложение).
- ffmpeg в CI есть; тесты аудио генерируют короткие файлы сами (синус/тишина), бинарники в репозиторий не коммитятся.
- Проверки, которым нужен GPU (`scripts/gpu_smoke.py`, замеры), помечаются `@pytest.mark.gpu` и в CI пропускаются.

## Чего не делать

- Не менять `docs/decisions/` и не принимать архитектурных решений сверх задачи — вынеси вопрос в PR.
- Не добавлять зависимости без фиксированной версии.
- Не использовать `gigaam.transcribe_longform` (тянет отдельную VAD-зависимость и HF-токен в рантайме) — нарезку делает `segment` по разметке pyannote.
- Не коммитить `.env`, `data/`, `models/`, аудио, реальные транскрипты и токены.
- Не ходить из тестов в сеть, Hugging Face и instudy.

```
pytest
ruff check . && ruff format --check .
docker compose build
docker compose run --rm transkrib python -m transkrib.cli models-check
docker compose up -d
docker compose exec transkrib python -m transkrib.cli status
```
