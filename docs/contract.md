## Что мы используем

| Что | Договор instudy | Где у нас |
| --- | --- | --- |
| Базовый адрес | `https://api.<домен>` (= `API_BASE_URL` instudy), только HTTPS | `INSTUDY_API_URL`; `http://` запрещён на старте (`config.py`) |
| Префикс | `/api/service/v1/` | `client.API_PREFIX` |
| Авторизация | `Authorization: Bearer <token>` на всех адресах, кроме аудио; cookie не работают | `client.InstudyClient` — отдельный HTTP-клиент для аудио, без `Authorization` |
| `GET /health` | `200 {"ok", "serverTime", "client", "paused"}` | старт демона, раз в 10 минут при пустой очереди, `cli check`; `paused` — в `state.json` и `cli status` |
| `GET /jobs/next` | `204` — нет работы (или выдача на паузе); `200 {"job": …}`; `503` — API не настроен | цикл демона: `204` → сон `POLL_INTERVAL_SEC`; `503` → повтор с задержкой |
| `POST /jobs/{id}/heartbeat` | `200 {"leaseUntil"}`; `410` — работа больше не наша | поток heartbeat раз в `HEARTBEAT_SEC` (300 с); `410` → отмена без `fail` |
| `GET {audioUrl}` | подписанная ссылка `…/audio/{dayId}?job=…&exp=…&sig=…`, `Range` → `206`; `403` — ссылка погасла | `client.download`: ссылка берётся как есть, докачка до 5 попыток; `403` → бросить работу без `fail` |
| `POST /jobs/{id}/result` | `multipart/form-data`: `vtt`, `txt` (файлы), `meta` (JSON-строка) | `client.submit_result` |
| `POST /jobs/{id}/fail` | `{"reason", "retryable", "message"}` → `204`; `410` — сообщать некому | `client.fail` |

### Поля работы

`id`, `dayId` — целые > 0; `date` — `YYYY-MM-DD`; `discipline` — строка ≤ 500 (для шапки `.txt`); `audioUrl` — ≤ 4096, тот же хост, что базовый адрес; `audioSizeBytes` — целое > 0; `audioDurationSec` — целое > 0 или `null`; `audioSha256` — 64 hex, есть всегда; `leaseUntil` — ISO 8601 UTC.

Клиент проверяет типы строго: `"412"` вместо `412` невалидно, лишние поля игнорируются. Ещё проверяется `audioSizeBytes ≤ MAX_AUDIO_BYTES`, `audioDurationSec ≤ MAX_AUDIO_SEC` и хост ссылки. Нарушение — `fail invalid_job` (`retryable: false`). После скачивания должны совпасть размер и SHA-256, иначе файл удаляется и уходит `fail download_failed` (`retryable: true`).

### Сроки

- Аренда — 30 минут от выдачи. Каждый heartbeat продлевает её ещё на 30 минут, но не дальше 4 часов от выдачи. Истёкшая без результата аренда засчитывается неудачей.
- Ссылка на аудио живёт 60 минут от выдачи, но гаснет раньше, если аренда потеряна. После начала обработки аудио повторно не нужно.
- Лимит запросов — 60 в минуту на токен. Демон делает ≈ 2 запроса в минуту: опрос раз в 60 с, heartbeat раз в 5 минут, health раз в 10 минут при пустой очереди.

### Коды ответов и что делает демон

| Код | Где | Действие |
| --- | --- | --- |
| `401` | везде | Выдача останавливается, критическая запись в лог, проверка раз в 10 минут |
| `429` | везде | Ждать `Retry-After` (целые секунды) |
| `5xx`, `503`, сеть | везде | Повтор с экспоненциальной задержкой 5 с → 5 мин |
| `410` | heartbeat, result, fail | Работа не наша: отмена, уборка, `fail` не слать (`409` на heartbeat и fail обрабатывается так же — для совместимости, договор его не отдаёт) |
| `403` | аудио | Ссылка погасла: бросить работу без `fail`, аренда истечёт сама |
| `202` | result | Готово; тело `{"transcriptId": …}` не используется |
| `409` | result | У дня уже есть транскрипт (участник загрузил раньше): закрыто, без `fail` |
| `400` | result | Форма оборвалась при отправке: повторять, пока жива аренда, как `5xx` |
| `413` | result | `fail result_too_large` (`retryable: false`). Лимиты проверяются ещё до отправки (ниже) |
| `415`, `422` | result | `fail result_rejected` (`retryable: false`) + критическая запись в лог: это баг клиента |

### Коды `reason`

| Код | Когда | `retryable` |
| --- | --- | --- |
| `download_failed` | Не скачалось, не совпали размер или SHA-256 | да |
| `decode_failed` | ffmpeg не разобрал аудио | нет |
| `no_speech` | Речи нет (диаризация пустая или ASR не дал текста); пустой результат не шлётся | нет |
| `oom` | Нехватка памяти GPU (повтор куска не помог) | да |
| `model_error` | Иная ошибка модели | да |
| `invalid_job` | Работа не прошла проверку клиента | нет |
| `result_too_large` / `result_rejected` | Лимиты результата / `415`, `422` на result | нет |
| `shutdown` | Остановка демона посреди работы, а также неисправность сервера (модели не грузятся) | да, попытка **не засчитывается** |

instudy при `retryable: true` возвращает работу в очередь и засчитывает попытку. Исключение — `shutdown`, он попытку не засчитывает. При `retryable: false` работа сразу становится `failed`. Третья засчитанная неудача — тоже `failed`. `message` — до 300 символов, без путей, токенов, ссылок и трассировок (`client.sanitize_message`).

### Лимиты результата

Каждый файл ≤ 10 МиБ, `meta` ≤ 4096 байт, всё тело ≤ 50 МиБ. Превышение клиент находит до отправки и сразу шлёт `fail result_too_large` (`client.check_result_size`). Для ориентира: 5 часов речи — около 0,4 МБ `.txt` и 1 МБ `.vtt`.

Перед API тело ограничивает Caddy instudy: с OPS-2 (instudy#49) — `max_size 51MiB`, больше лимита API. До OPS-2 там было `51MB` = 51 000 000 байт, меньше 50 МиБ, и тело от ≈ 48,6 до 50 МиБ резал бы Caddy. Его `413` приходит с пустым телом, клиент смотрит только на код и отвечает тем же `fail result_too_large` (тест `test_caddy_413_without_body_is_result_too_large`). В договоре instudy пока написано `51MB`: правка текста — задача instudy DOC-1.

## Формат результата

Оба файла — UTF-8 без BOM, переводы строк `\n`. Полные правила и примеры — в договоре, раздел «Формат результата».

**`.vtt`** (`render.render_vtt`): instudy проверяет его строго, нарушение даёт `422`.
- Первая строка `WEBVTT`, за ней пустая.
- Реплики разделены пустой строкой. Каждая: номер, `ЧЧ:ММ:СС.ммм --> ЧЧ:ММ:СС.ммм` без настроек реплики, затем текст.
- Начала реплик не убывают, таймкоды не больше 12 часов; если больше, `render` отказывается рендерить.
- Голос — только `<v Спикер N>`, N от 1 до 99, по порядку первого появления. Спикеры сверх 99 сливаются в «Спикер 99» (`render.MAX_SPEAKERS`).
- Других тегов и блоков `NOTE`/`STYLE`/`REGION` нет. `&`, `<`, `>` экранируются. Пустых реплик нет.

**`.txt`** (`render.render_txt`):
- Шапка: «Дисциплина — ДД.ММ.ГГГГ» и строка `Автотранскрипт: GigaAM v3 e2e RNNT, pyannote community-1`, затем пустая строка.
- Абзацы `[ЧЧ:ММ:СС] Спикер N: текст` через пустую строку.
- Подряд идущие реплики одного спикера — один абзац. Новый абзац начинается после паузы больше 60 с или если абзац длиннее 3 минут.
- Без экранирования HTML. instudy проверяет только кодировку, управляющие символы и что файл не пустой.

**`meta`** (`render.build_meta`): `server` (≤ 100), `asr` и `diarization` (≤ 200) — обязательные. Необязательные: `audioDurationSec`, `processingSec`, `segments` — целые ≥ 0, `speakers` — целое 1–99. Неизвестные поля instudy отбрасывает. Секретов в `meta` нет: участники её видят.

## Выкладка instudy (проверить перед боевым запуском)

- В instudy задан `SERVICE_LINK_SECRET` (≥ 32 байт), иначе `jobs/next` отвечает `503`, а любая ссылка на аудио — `403`.
- Хост базового адреса instudy (`API_BASE_URL` или `https://api.<DOMAIN>`) совпадает с хостом `INSTUDY_API_URL`. Иначе каждая работа приходит с «чужой» ссылкой и получает `invalid_job`.
- Сервисный токен выдаётся командой `python -m app.cli service-add home-gpu`, отзывается — `service-revoke`. Выдачу ставит на паузу и снимает с неё админ (`autotx-pause`): для демона это `paused` в health и `204` на `jobs/next`, не ошибка.

## Решения клиента, которые договор подтвердил (бывшие пометки T-4)

| Решение | Итог сверки |
| --- | --- |
| `audioUrl` принимается только с хоста `INSTUDY_API_URL` | Договор: ссылка всегда на хосте базового адреса — проверка совместима |
| Строгие типы полей работы | Договор: целые и `null` для длительности — совпадает |
| `fail` после потери работы — норма, не ошибка | Договор: `410` — «сообщать некому» |
| `Retry-After` в секундах или HTTP-дата | Договор: всегда целые секунды (разбор даты оставлен) |
| `200` на `Range` — писать файл заново | Договор: корректный `Range` — всегда `206`; запасной путь оставлен |
| Имена файлов в форме не используются | Договор: instudy называет файлы сам (`<дата>_<дисциплина>.<ext>`) |
| `shutdown` не засчитывается в попытки | Договор: так и есть; `shutdown` шлём и при неисправности сервера (T-6a) |
| `no_speech` — `fail` без повтора | Договор: `fail`, `retryable: false`, пустой транскрипт не создаётся |
