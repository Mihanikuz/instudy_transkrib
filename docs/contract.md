> **Статус: черновик.** Сервисный API в instudy ещё проектируется ([PR #35](https://github.com/Mihanikuz/instudy/pull/35) — промт архитектора ARCH-2 → задачи BE-14 и следующие в instudy). После их слияния источником истины станет `instudy/docs/transcription-api.md` (договор для сервера транскрибации, задуман в BE-14), а этот файл сверяется с ним в задаче T-9. До тех пор код пишется по этому черновику, и все расхождения закрывает T-9.

## Общее

- Базовый адрес — `INSTUDY_API_URL` (например, `https://api.<домен>`), только HTTPS.
- Авторизация — заголовок `Authorization: Bearer <SERVICE_TOKEN>` на каждом запросе к `/api/service/v1/*`. Cookie не используются.
- Ошибки — JSON `{"detail": "…"}`. `401` — токен неверный или отозван (демон останавливает выдачу и пишет в лог критическую ошибку, повторяет раз в 10 минут). `429` — ждать `Retry-After`. `5xx` и сетевые ошибки — повтор с экспоненциальной задержкой (5 с → 5 мин).
- Лимит instudy — 60 запросов в минуту на токен. Демон укладывается с запасом: опрос пустой очереди раз в `POLL_INTERVAL_SEC` (по умолчанию 60 с), heartbeat раз в 5 минут.

## Жизненный цикл работы

```
GET jobs/next ──► (аренда) ──► скачать audioUrl ──► обработать ──► POST result ──► готово
                     │                                  │
                     ├── POST heartbeat каждые 5 мин ───┤
                     │   409/410 → бросить работу       │
                     └──────────── POST fail ◄──────────┘ (ошибка, остановка)
```

### `GET /api/service/v1/health`
`200 {"ok": true, "serverTime": "2026-10-22T13:00:00Z", "client": "home-gpu"}` — проверка токена и связности при старте демона и в `cli check`.

### `GET /api/service/v1/jobs/next`
`204` — работы нет. `200`:
```json
{
  "job": {
    "id": 731,
    "dayId": 412,
    "date": "2026-09-29",
    "discipline": "Общая психология",
    "audioUrl": "https://api.<домен>/api/service/v1/audio/412?exp=1761140400&sig=…",
    "audioSizeBytes": 108234567,
    "audioDurationSec": 17940,
    "leaseUntil": "2026-10-22T13:30:00Z"
  }
}
```
Демон проверяет: `id`, `dayId` — положительные целые; `audioSizeBytes` ≤ `MAX_AUDIO_BYTES` (по умолчанию 300 МБ); `audioDurationSec` ≤ `MAX_AUDIO_SEC` (по умолчанию 6 ч). Нарушение — `fail` с `invalid_job`, `retryable: false`.

### Скачивание аудио — `GET {audioUrl}`
Без `Authorization` (ссылка подписана). Поддерживается `Range` → `206`, демон докачивает после обрыва. `403` — срок ссылки истёк: работа бросается без `fail` (аренда истечёт сама и работа вернётся в очередь). Скачанный размер должен совпасть с `audioSizeBytes`, иначе `download_failed`.

### `POST /api/service/v1/jobs/{id}/heartbeat`
`200 {"leaseUntil": "…"}` — аренда продлена. `409`/`410` — работа больше не наша (аренда истекла и выдана снова, день исчез, транскрипт уже загрузили вручную): демон немедленно прекращает обработку, удаляет рабочие файлы, `fail` не шлёт.

### `POST /api/service/v1/jobs/{id}/result`
`multipart/form-data`, поля:

| Поле | Тип | Содержимое |
| --- | --- | --- |
| `vtt` | файл `text/vtt; charset=utf-8` | Субтитры, формат ниже |
| `txt` | файл `text/plain; charset=utf-8` | Текст, формат ниже |
| `meta` | JSON-строка | Метаданные, формат ниже |

| Код | Значение | Действие демона |
| --- | --- | --- |
| `202` | Принято, instudy обработает как обычный транскрипт | Готово, очистить рабочие файлы |
| `409` | У дня уже есть активный транскрипт (загружен вручную) | Не ошибка: работа закрыта, очистить |
| `410` | Работа не наша / аренда истекла / день исчез | Очистить, `fail` не слать |
| `413` | Слишком большой результат | `fail` `result_too_large`, `retryable: false` |
| `415`, `422` | instudy не принял формат | `fail` `result_rejected`, `retryable: false`; это баг — критическая запись в лог |
| `5xx`, сеть | — | Повторять, пока жива аренда (heartbeat продолжает работать) |

### `POST /api/service/v1/jobs/{id}/fail`
`{"reason": "oom", "retryable": true, "message": "CUDA out of memory на диаризации"}` → `204`. После 3 неудач instudy перестаёт выдавать день.

Коды `reason`:

| Код | Когда | `retryable` |
| --- | --- | --- |
| `download_failed` | Не скачалось или не совпал размер | да |
| `decode_failed` | ffmpeg не смог разобрать аудио | нет |
| `no_speech` | Диаризация не нашла речи | нет |
| `oom` | Нехватка памяти GPU даже после понижения пакета | да |
| `model_error` | Иная ошибка модели | да |
| `invalid_job` | Работа не прошла проверку | нет |
| `result_too_large` / `result_rejected` | См. таблицу результата | нет |
| `shutdown` | Демон останавливают посреди работы | да |

`message` — до 300 символов, без путей, токенов, ссылок и трассировок.

## Формат результата

### `.vtt`

```
WEBVTT

1
00:00:03.120 --> 00:00:09.860
<v Спикер 1>Добрый день, коллеги. Сегодня продолжаем тему внимания.

2
00:00:10.200 --> 00:00:14.050
<v Спикер 2>А можно уточнить про прошлое задание?
```

- UTF-8 без BOM, переводы строк `\n`, после `WEBVTT` пустая строка.
- Одна реплика (cue) — один распознанный сегмент (не длиннее 25 с). Таймкоды `ЧЧ:ММ:СС.ммм`, возрастают, не пересекаются.
- Голос — всегда `<v Спикер N>`, N с 1, по порядку первого появления. Сегменты без надёжного спикера получают спикера соседнего сегмента с наибольшим перекрытием; голоса без номера не бывает.
- Текст экранируется: `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`. Пустые сегменты не пишутся.

### `.txt`

```
Общая психология — 29.09.2026
Автотранскрипт: GigaAM v3 e2e RNNT, pyannote community-1

[00:00:03] Спикер 1: Добрый день, коллеги. Сегодня продолжаем тему внимания.

[00:00:10] Спикер 2: А можно уточнить про прошлое задание?
```

- UTF-8 без BOM, `\n`.
- Подряд идущие сегменты одного спикера объединяются в абзац; новый абзац того же спикера начинается, если пауза больше 60 с или абзац длиннее 3 минут (с новым таймкодом).
- Таймкод — начало абзаца, `[ЧЧ:ММ:СС]`.

### `meta`

```json
{
  "server": "instudy_transkrib 0.1.0",
  "asr": "gigaam v3_e2e_rnnt @<commit>",
  "diarization": "pyannote/speaker-diarization-community-1",
  "audioDurationSec": 17940,
  "processingSec": 912,
  "speakers": 4,
  "segments": 1873
}
```

## Открытые вопросы к instudy

1. Что делать при `no_speech`: сейчас — `fail` без повтора. Альтернатива — пустой результат.
2. Будут ли `audioSha256` в задании (для проверки целостности вместо одного размера).
3. Нужен ли IP-allowlist на `/api/service/v1/*` (у сервера домашний адрес, возможно динамический).
