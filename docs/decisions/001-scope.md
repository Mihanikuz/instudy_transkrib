# 001 · Объём и границы сервера транскрибации

Oct 22, 2026 · @Mikhail

## Решение

| Вопрос | Решение |
| --- | --- |
| Модели | ASR — GigaAM `v3_e2e_rnnt` (с пунктуацией и нормализацией). Диаризация — `pyannote/speaker-diarization-community-1`. Multilingual-линейка GigaAM не используется: на русском она точнее, но это CTC без пунктуации |
| Железо | Домашний сервер Ubuntu 26.04, i7-12700, 61 ГБ ОЗУ, RTX 5060 Ti 16 ГБ (драйвер 595.99, CUDA 12.8 в контейнерах). Видеокарта отдана серверу целиком: gigascribe и fish-s1 остановлены, автозапуск выключен |
| Сеть | Сервер за NAT. Только pull: демон сам ходит в `api.<домен>`, входящих подключений нет |
| Длина записей | До 5 часов |
| Результат | Два файла: `.vtt` (для плеера) и `.txt` (для скачивания и чтения) |
| Имена | Не подставляются. Только «Спикер 1», «Спикер 2»… по порядку первого появления |
| Плеер на сайте | Пока нет; `.vtt` скачивается и открывается вместе с `.m4a` в VLC/mpv. Плеер — отдельная задача instudy «на потом» |
| Очередь | Все дни с аудио, включая архив, от самых старых к новым (`date ASC, id ASC`). Порядок задаёт instudy |
| Пауза перед обработкой | Нет: день доступен, как только готово аудио |
| Ручная загрузка | Главный путь. Если студент загрузил транскрипт раньше, автоматический не создаётся (instudy отвечает 409) |
| Права на автотранскрипт | Заменить или удалить — только админ instudy |
| Интерфейс | Без веба: демон, логи, CLI |

## Почему

- `v3_e2e_rnnt` даёт текст с пунктуацией — его можно читать без постобработки; проверена в gigascribe на этой же карте.
- pyannote community-1 работает офлайн после разовой загрузки и заодно даёт разметку речи, по которой режется аудио под ограничение GigaAM в 25 секунд.
- Pull снимает вопрос проброса портов и делает instudy единственным хозяином очереди.

## Вне объёма

Подстановка имён (по расписанию, голосовой банк, NER, LLM), CPU-режим, протоколы и резюме, веб-интерфейс, несколько GPU и параллельные работы.
