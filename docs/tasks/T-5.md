# T-5 · Конвейер одной записи

```
Прочитай CLAUDE.md, docs/architecture.md («Обработка одной работы», шаги 4–8, «Ошибки и устойчивость»), docs/contract.md («Формат результата», коды reason). Опирайся на T-2 (протоколы Recognizer/Diarizer, фейки) и T-3 (Segment, render). Ты — senior Python/ML-разработчик.

Сделай:
1. transkrib/audio.py: to_wav16k_mono(src, dst) через ffmpeg (subprocess с таймаутом, вся группа процессов убивается при отмене/таймауте), probe_duration(path) через ffprobe, load_wav(path) -> numpy float32 через стандартный wave/numpy (без torch), rms_frames(samples, frame_ms=30). Ошибка ffmpeg → PipelineError("decode_failed"), stderr в лог без путей пользователя (только имя job-каталога).
2. transkrib/segment.py — чистые функции по шагу 6 архитектуры: merge_turns(turns, max_gap=0.5), split_long(region, samples, max_sec=22, hard_sec=24, window=(15, 22)) по минимуму RMS, drop_short(min_sec=0.3), number_speakers(turns) — метки pyannote → номера 1, 2, 3… по первому появлению (Segment.speaker: int; подпись «Спикер N» делает render). Параметры — из конфига.
3. transkrib/pipeline.py: run(wav_or_m4a, *, diarizer, recognizer, cancel: threading.Event, progress: Callable) -> PipelineResult(segments: list[Segment], speakers, duration_sec, processing_sec, skipped_chunks). Порядок: подготовка WAV → диаризация (потом unload, если KEEP_MODELS_LOADED=false) → нарезка → ASR по кускам (проверка cancel перед каждым куском) → сегменты. Пустая разметка → PipelineError("no_speech"). Ошибка отдельного куска — пропуск с предупреждением; доля пропусков > 5 % → PipelineError("model_error"). CUDA OOM (распознаётся по типу/тексту исключения без импорта torch на уровне модуля) → empty_cache и один повтор куска, повторный OOM → PipelineError("oom"). Отмена → PipelineCancelled. Прогресс: этап и доля обработанных кусков.
4. CLI run-file <audio> [--out DIR] — прогон конвейера на локальном файле с настоящими моделями (для человека на сервере): пишет .vtt, .txt, meta.json, печатает время по этапам и пиковую VRAM. Без instudy и без токена.

Критерии приёмки (pytest, фейковые модели, ffmpeg из CI):
- синтетический WAV (тон/тишина, сгенерирован в тесте) 90 с → to_wav16k_mono даёт 16 кГц моно, длительность совпадает ±50 мс;
- merge_turns склеивает одного спикера при паузе 0,3 с и не склеивает при 0,8 с и при смене спикера;
- split_long режет 70-секундный отрезок на куски ≤ 22 с (никогда > 24 с) и выбирает точку тишины, заложенную в сигнал;
- number_speakers: SPEAKER_03, SPEAKER_00, SPEAKER_03, SPEAKER_01 → 1, 2, 1, 3;
- конвейер на фейках возвращает сегменты, которые проходят render_vtt/render_txt из T-3;
- отмена посреди ASR → PipelineCancelled, recognizer больше не вызывается;
- пустая разметка → no_speech; 10 % падающих кусков → model_error; 2 % → успех и skipped_chunks = число падений;
- OOM на куске один раз → повтор и успех; дважды → oom;
- битый входной файл → decode_failed.
Проверяет человек: cli run-file на реальной лекции, вывод и файлы приложить к PR (без текста лекции в публичном PR — только метрики и 10 строк .txt с согласия).
```
