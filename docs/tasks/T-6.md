# T-6 · Демон: аренда, heartbeat, результат, отказ, сигналы, CLI

```
Прочитай CLAUDE.md, docs/architecture.md целиком (особенно «Обработка одной работы» шаги 1–3 и 9–10, «Ошибки и устойчивость», «Конфигурация»), docs/contract.md. Опирайся на T-4 (client, fake_instudy) и T-5 (pipeline). Ты — senior Python-разработчик.

Сделай:
1. transkrib/daemon.py — главный цикл python -m transkrib:
   - старт: очистка data/work/, проверка моделей (models_store.check), health() у instudy (401 → критический лог и ожидание по правилу из архитектуры), запись state.json;
   - цикл: пауза (data/PAUSE) → проверка свободного места (MIN_FREE_GB) → next_job → heartbeat-поток → download → pipeline → render → submit_result → уборка → копия в data/results/<job_id>/ → следующая итерация; пустая очередь — сон POLL_INTERVAL_SEC (прерываемый сигналом);
   - heartbeat-поток: каждые HEARTBEAT_SEC; LeaseLost → cancel.set(); Transient — повтор в следующий тик; поток гарантированно останавливается после работы;
   - повторы Transient/RateLimited с экспоненциальной задержкой 5 с → 5 мин (с учётом Retry-After); submit_result повторяется, пока аренда жива;
   - классификация исходов по таблицам контракта: какие исходы шлют fail (с каким reason и retryable), какие — нет (LeaseLost, LinkExpired, 409/410 на result);
   - SIGTERM/SIGINT: cancel.set(), fail shutdown (retryable) для текущей работы, уборка, выход за ≤ 30 с; второй сигнал — немедленный выход;
   - ежесуточная чистка data/results старше RESULTS_KEEP_DAYS.
   - сервер не должен «сжигать» попытки дней из-за своих проблем (по ревью T-5): проблемы GPU и моделей — это неисправность сервера, а не дня. На старте — загрузить обе модели (load) до первой аренды; не грузятся (CUDA недоступна, driver/library mismatch, нет моделей) — статус error, работу не брать, повтор раз в 10 минут. ModelError при загрузке посреди работы — fail shutdown (retryable) и переход в error с тем же повтором. Предохранитель: 3 работы подряд закончились model_error или oom — пауза выдачи со статусом error и критической записью в лог (иначе сломанный сервер за час переведёт в failed весь архив);
   - ValueError рендера (нет ни одного сегмента с текстом после удаления заполнителей) — тот же исход, что no_speech.
2. transkrib/state.py — атомарная запись data/state.json (tmp + rename): pid, версия, started_at, heartbeat_at (обновляется каждые 30 с и на каждом этапе), status (idle/paused/working/error), текущая работа (id, dayId, date, этап, прогресс, начало), счётчики done/failed/skipped/cancelled с начала работы, последняя ошибка (код, время). Никаких токенов, ссылок и текстов.
3. CLI: status (человекочитаемо из state.json), pause / resume (файл PAUSE), check (health instudy + models-check + nvidia-smi при наличии), health (код 0, если heartbeat_at свежее 180 с — для healthcheck Docker).

Критерии приёмки (pytest, фейковый instudy + фейковые модели, подменяемые часы):
- полный цикл: работа выдана → скачана → обработана → result 202 → data/work пуст, data/results/<id>/ содержит vtt, txt, meta.json;
- 409 на result → работа закрыта без fail; 410 → без fail;
- LeaseLost на heartbeat посреди ASR → обработка остановлена, fail не отправлен, data/work пуст;
- исключение no_speech/decode_failed/oom → fail с правильными reason и retryable;
- 5xx на result дважды, затем 202 → результат принят, один набор файлов;
- SIGTERM посреди работы → fail shutdown retryable, процесс выходит, data/work пуст;
- PAUSE → next_job не вызывается; resume → вызывается;
- нехватка места (подменённый disk_usage) → работа не берётся, статус paused с причиной;
- 401 на старте → выдача не начинается, повтор через 10 минут (подменённые часы);
- state.json валиден после каждого шага и не содержит токена и query ссылки (поиск подстроки);
- cli health: свежий heartbeat → 0, старый → 1.
- модели не загрузились на старте → next_job не вызывается ни разу, статус error, повтор через 10 минут (подменённые часы);
- ModelError при загрузке модели посреди работы → fail shutdown retryable, дальше работа не берётся до успешной загрузки;
- три работы подряд с model_error → четвёртая не берётся, статус error; успешная загрузка после повтора снимает блокировку.
```
