```
Прочитай CLAUDE.md, docs/architecture.md («Окружение», «Развёртывание», «Безопасность», «Конфигурация»). Ты — senior DevOps-инженер. Целевой сервер: Ubuntu 26.04, Docker 29.1, Compose 2.40, NVIDIA Container Toolkit 1.19, RTX 5060 Ti (sm_120), драйвер 595.99. Опыт сборки этой же связки — Dockerfile gigascribe (закрепление базового образа по кодовому имени Debian, constraints для torch).

Сделай:
1. Dockerfile: многоступенчатый, база python:3.12-slim-bookworm (или 3.11 — как решил T-1) закреплена по digest; ffmpeg из Debian; requirements-gpu.txt с --require-hashes и constraints; пользователь uid 10001; ENV HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 PYANNOTE_METRICS_ENABLED=0 PYTHONDONTWRITEBYTECODE=1; ENTRYPOINT через tini; без моделей внутри образа.
2. compose.yml: сервис transkrib — gpus: all, restart: unless-stopped, user 10001, read_only: true, tmpfs /tmp (размер под нарезку кусков), volumes ./models:/models:ro и ./data:/data, env_file не используется — environment: со списком переменных из .env, без ports:, stop_grace_period: 45s, healthcheck python -m transkrib.cli health, logging json-file 10m×5. Отдельный профиль/сервис models для models-download/models-import с ./models:/models (rw) и HF_TOKEN — только он видит HF_TOKEN.
3. README.md — разделы: «Что это», «Требования» (с командой проверки GPU в Docker), «Первая установка» (клон в /srv/transkrib, .env с chmod 600, chown 10001 data/, перенос моделей из gigascribe через models-import или загрузка с HF_TOKEN, cli check, cli run-file на тестовой записи, docker compose up -d), «Получение токена» (админ instudy: python -m app.cli service-add home-gpu, вставить в .env), «Эксплуатация» (status, pause/resume, логи, где результаты), «Обновление» (git pull, build, up -d — текущая работа корректно вернётся в очередь), «Отзыв токена и остановка», «Если что-то не так» (driver/library version mismatch → перезагрузка; OOM; 401).
4. deploy/update.sh: git pull --ff-only, docker compose build, docker compose up -d, ожидание healthcheck, вывод cli status.
5. Находки проверок на сервере 22–23.10 (отчёт docs/experiments/2026-10-22-asr-models.md):
   - ENV MPLCONFIGDIR=/tmp/matplotlib — pyannote тянет matplotlib, а он пишет кэш шрифтов; с read_only упадёт;
   - предупреждение torchcodec «libnppicc.so.12» безвредно (аудио идёт в pyannote массивом) — заглушить фильтром warnings в diarize.load(), а не ставить CUDA NPP в образ;
   - файлы data/ создаёт uid 10001: в README — sudo chown -R 10001:10001 data/ и как читать результаты от своего пользователя (группа или sudo);
   - модели gigascribe на сервере лежат в /opt/gigascribe/models — пример models-import в README с этим путём;
   - на хосте уже есть служба Ollama, слушающая *:11434 без пароля: в README раздел «Чужие сервисы на GPU» — выключить или привязать к 127.0.0.1, они делят видеопамять.
6. CI: сборка образа без GPU (docker build) и hadolint; проверка, что в образе нет каталога моделей и запускается python -m transkrib.cli version.

Критерии приёмки:
- docker build проходит в CI; образ запускается не от root; cli version работает в контейнере;
- pytest-проверки compose.yml (yaml): нет ports, read_only true, models смонтирован ro у основного сервиса, HF_TOKEN есть только у сервиса загрузки моделей, SERVICE_TOKEN — только у основного;
- README проходит по шагам на чистом клоне (проверяет человек на сервере; результат — в PR).
```
