# T-4 · Клиент сервисного API instudy и фейковый instudy

```
Прочитай CLAUDE.md, docs/contract.md целиком, docs/architecture.md («Ошибки и устойчивость», «Безопасность»). Ты — senior Python-разработчик. Сервисный API в instudy ещё не реализован — работаешь по черновику контракта. Если найдёшь в контракте неоднозначность — реши в коде самым безопасным способом, допиши в docs/contract.md пометку «уточнить в T-9» и перечисли в PR.

Сделай:
1. transkrib/client.py — синхронный клиент на httpx (демон однопоточный, heartbeat — отдельный поток со своим клиентом):
   - health(), next_job() -> Job | None, heartbeat(job_id) -> lease_until, download(job, dest, *, cancel) с докачкой по Range и проверкой размера, submit_result(job_id, vtt: bytes, txt: bytes, meta: dict) -> ResultOutcome (accepted | already_has_transcript | gone), fail(job_id, reason, retryable, message);
   - типизированные исключения: Unauthorized, LeaseLost (409/410 на heartbeat), LinkExpired (403 на audioUrl), Rejected (413/415/422), RateLimited(retry_after), Transient (5xx, сеть, таймауты);
   - Job — pydantic-модель с проверками из контракта (положительные id, лимиты размера и длительности из конфига); невалидная работа → InvalidJob;
   - Bearer только на /api/service/*, на audioUrl — без Authorization; TLS-проверка всегда включена; таймауты: 10 с на соединение, 60 с на чтение, скачивание потоковое с проверкой флага отмены каждые 1 МБ;
   - message в fail обрезается до 300 символов и прогоняется через тот же фильтр секретов, что и логи; reason — только из перечисления контракта;
   - повторы с экспоненциальной задержкой — не в клиенте, а в вызывающем коде (T-6); клиент только классифицирует ошибки.
2. tests/fake_instudy.py — ASGI-приложение (Starlette/FastAPI в requirements-dev, версия зафиксирована) или httpx.MockTransport, моделирующее контракт: очередь работ, аренды с истечением (подменяемые часы), heartbeat, подписанные ссылки с exp, Range, 409 при «ручной загрузке», 410 при «исчезнувшем дне», 401 при неверном токене, 429 с Retry-After, сбои 5xx по сценарию, журнал всех запросов для проверок.

Критерии приёмки (pytest, только фейковый instudy, сеть запрещена):
- 204 → None; 200 → Job; работа с audioSizeBytes больше лимита → InvalidJob;
- обрыв скачивания посередине → докачка по Range, итоговый файл совпадает побайтно; несовпадение размера → ошибка download_failed;
- 403 на audioUrl → LinkExpired; 409 и 410 на heartbeat → LeaseLost; 401 → Unauthorized; 429 → RateLimited с секундами из Retry-After;
- submit_result: 202 → accepted, 409 → already_has_transcript, 410 → gone, 422 → Rejected; multipart содержит ровно поля vtt, txt, meta с правильными content-type и charset;
- в журнале фейка: Authorization есть на всех /api/service/* и отсутствует на audioUrl;
- ни токен, ни query audioUrl не попадают в логи (caplog) и в текст исключений;
- fail с message, содержащим токен и ссылку, отправляется уже замаскированным и не длиннее 300 символов.
```
