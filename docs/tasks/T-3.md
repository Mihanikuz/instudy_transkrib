# T-3 · Рендер `.vtt` и `.txt`

```
Прочитай CLAUDE.md и docs/contract.md, раздел «Формат результата» — это спецификация, по которой работаешь. Ты — senior Python-разработчик.

Сделай transkrib/render.py — чистые функции без ввода-вывода:
1. Модель данных Segment(start: float, end: float, speaker: int, text: str) — общая для конвейера (положи в transkrib/types.py, её импортируют T-5 и T-6).
2. render_vtt(segments) -> str — строго по контракту: заголовок WEBVTT, нумерованные cue, таймкоды ЧЧ:ММ:СС.ммм (часы всегда двумя цифрами, записи до 6 часов), голос <v Спикер N>, экранирование & < >, пустые тексты пропускаются, cue упорядочены и не пересекаются (при пересечении конец предыдущего подрезается до начала следующего).
3. render_txt(segments, *, discipline, date, engine_line) -> str — шапка из двух строк и пустая строка; абзацы «[ЧЧ:ММ:СС] Спикер N: текст»; склейка подряд идущих сегментов одного спикера; новый абзац при смене спикера, паузе > 60 с или длине абзаца > 180 с; пробелы между сегментами нормализуются (без двойных пробелов и пробела перед знаком препинания).
4. build_meta(...) -> dict по контракту.
5. Проверка себя: validate_vtt(text) — повторно разбирает результат (тот же разбор, что в instudy: app/worker/transcript_extract.py extract_subtitles, перенеси логику разбора в тест как эталон) и сверяет число cue и голоса.

Критерии приёмки (pytest):
- золотые файлы tests/fixtures/render/*.vtt и *.txt для сценария из 3 спикеров, 7 сегментов, с паузой > 60 с и абзацем > 180 с — совпадают побайтно;
- UTF-8 без BOM, только \n, файл заканчивается переводом строки;
- таймкод 5:00:00.5 → 05:00:00.500 в vtt и [05:00:00] в txt;
- текст с <script> и & экранируется в vtt и остаётся как есть в txt;
- пустой список сегментов → ValueError (пустой результат не отправляется — это no_speech у конвейера);
- голоса только вида «Спикер N», N ≥ 1, без пропусков номеров.
```
