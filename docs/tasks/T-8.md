# T-8 · Замеры и качество на реальных записях

```
Прочитай CLAUDE.md, docs/architecture.md («Производительность», «Обработка одной работы»). Ты — ML-инженер. Задача выполняется вместе с человеком: он запускает команды на GPU-сервере и присылает вывод; ты готовишь скрипты, анализируешь результаты и предлагаешь значения настроек. Текст лекций в репозиторий и в PR не попадает.

Сделай:
1. scripts/bench.py (маркер gpu, запускается через docker compose run): прогон конвейера на списке локальных файлов с замером по этапам (подготовка, диаризация, нарезка, ASR, рендер), пиковой VRAM на каждом этапе (torch.cuda.max_memory_allocated + nvidia-smi), пиковой RSS, RTF, числа спикеров, кусков, пропущенных кусков; вывод — JSON и таблица. Режимы KEEP_MODELS_LOADED=true/false.
2. scripts/quality_sample.py: из результата выбирает 10 случайных фрагментов по 30 с (аудио + текст + спикер) в data/quality/ для ручного прослушивания человеком; оценочный лист quality.md (заполняет человек: ошибки слов, пунктуация, смена спикеров).
3. Прогоны на записях 1, 3 и 5 часов (человек выбирает их из data/audio instudy или скачивает вручную).
4. По итогам — PR с:
   - таблицей замеров в docs/architecture.md, раздел «Производительность» (заменить оценки фактами);
   - рекомендуемыми значениями MAX_SEGMENT_SEC, KEEP_MODELS_LOADED, HEARTBEAT_SEC (при необходимости) в .env.example и конфиге;
   - выводом: проходит ли 5-часовая запись одним вызовом pyannote. Если нет (OOM, > 30 мин, > 32 ГБ RAM) — промт задачи T-10 (окна по 60 мин со сшивкой) в docs/tasks/T-10.md;
   - сводкой качества по оценочному листу и списком типичных ошибок (без цитат лекций).

Критерии приёмки:
- bench.py и quality_sample.py проходят ruff и тест «сухого прогона» на фейковых моделях;
- в PR приложены JSON замеров трёх записей и заполненный человеком лист качества (без текста).
```
